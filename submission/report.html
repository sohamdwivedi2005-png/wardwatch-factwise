Q1) User types in the first version and what each of them can do

For V1 I'm keeping it to the staff who actually touch the process every day. Patients wont log in to the app in the first version since they dont need to do anything in it, a patient/family view can come later.

1. Nurse

  • Sees the list of all patients for today and which ones still need there temperature taken (pending vs done + a count like 41/74).
  • Records the temperature, only once per patient per day. App shows straight away if its a fever or not.
  • Can correct her own reading on the same day if she typed it wrong (within 2 hrs).
  • Can see the patients past readings and how many fever free days they have.
  • Gets a notification when a doctor asks for a reading for a particular bed.

2. Doctor

  • Visit list split into: ready for visit (temp already taken), waiting for temperature, and already visited today. So doctors dont go to a patient before the nurse has been.
  • Opens a patient and sees the temperature graph + previous visits.
  • Logs the visit with notes and treatment given.
  • When the system shows a patient has 3 fever free days in a row, doctor signs off the discharge in one click.
  • Records a death if it happens.
  • Can enter a temperature himself only if no nurse is available (has to give reason).

3. Admin staff

  • Bed board for all 74 beds showing which are occupied, eligible for discharge, cleared, or free.
  • Discharge list of patients the doctor has cleared, with how long they have been waiting. Admin completes discharge and the bed becomes free.
  • Can see upcoming discharges early so the next admission can be planned.
  • Admits a new patient into a free bed, records transfers.
  • Admin cannot see clinical notes or enter temperatures.

4. Head doctor

  • Everything a doctor can do.
  • A dashboard showing mortality rate (last 30 days and overall) against the 15% benchmark, success rate vs 85%, occupancy, average stay, how long discharges are getting delayed, and % of patients whose temperature / visit was done today.
  • Gets an alert if mortality goes above 15% or if discharges are stuck for more than 4 hours.

How this fixes the problems the head doctor mentioned:

ProblemWhat V1 does
Temperature taken twice or not at allOnly one reading allowed per day, nurses have a pending list
Doctor visits before temperature is takenVisit can't be logged until reading is there, queue shows who is ready
Patients staying extra 1-2 daysApp detects the 3 day rule automatically and tells doctor + admin immediately
No way to measure vs 85% benchmarkEvery patient exit recorded as recovered / died / transferred, shown on dashboard

Not in V1 (later): patient/family portal, other vitals, medicines record, staff rostering, SMS alerts, EMR integration, offline mode.

Q3) Extra logic / constraints for developers

Temperature

  • Fever = 38.0 C (100.4 F) or above. Store in Celcius with 1 decimal.
  • Only allow 34 to 43 C, anything outside is an error. Below 35 or 41 and above should show a warning asking the nurse to re-check and confirm. If 41+ is confirmed, doctors get an urgent alert.
  • One reading per patient per day (day = midnight to midnight). Once recorded, the button is replaced by the value, who took it and when.
  • Nurse can edit only her own reading, same day, within 2 hours. Doctor can edit with a reason. Keep history of every edit, nothing gets deleted.
  • No readings for future dates. Old dates only by doctor with reason and marked as late.
  • Admin can't enter temperatures. Doctor can but has to give reason (we track this to see staffing gaps).
  • No readings for discharged / dead / transferred patients.

Fever free days and discharge

  • Count = number of days in a row with a reading below 38. A fever resets it to 0. If a day has no reading it also breaks the count, we shouldn't assume it was fever free.
  • When count reaches 3 the patient becomes 'eligible' automatically and doctor and admin both get notified.
  • Only doctor can sign off and only if patient is eligible. Only admin can complete discharge and only after sign off.
  • If a fever is recorded after the patient became eligible/cleared, it gets cancelled automatically and both are told.
  • If eligible for more than 4 hrs without sign off, head doctor is alerted. Same if cleared but admin hasn't discharged in 4 hrs.
  • Head doctor can override and discharge with a reason, these are shown seperately.

Doctor visits

  • Doctor can't log the daily visit until temperature is recorded, show 'awaiting temperature' and a button to notify the nurse.
  • One main visit per patient per day, extra visits are logged as follow ups.
  • Visit notes are compulsory.

Beds, admission, death

  • Admit only into a free bed, max 74. When full, the admit button is disabled and shows the next expected discharge.
  • One patient per bed. Bed gets freed only by discharge, death or transfer.
  • Warn if same name + age is already admitted (possible duplicate).
  • Only doctor can record a death, with time and note and a confirm popup. Can't be undone except by head doctor with reason.
  • Transfers are recorded by admin with reason and are not counted in mortality.

Metrics

  • Mortality = deaths / (recovered + deaths), only for closed cases. Current patients and transfers are not counted. Success rate = 100% - mortality.
  • Show both last 30 days and overall. Only show the red alert if 30 day mortality is above 15% AND there are atleast 20 closed cases, otherwise a few deaths would trigger false alarms.
  • Daily compliance = % of current patients with todays reading and % with todays visit. Freeze the number at midnight for the trend.
  • Discharge delay = time from eligible to discharged, target under 4 hours.

Access and general

  • Role permissions should be checked on the backend also, not just hidden on screen. Admin can't see clinical notes. (In the prototype this is only done in the browser since there is no backend.)
  • Every staff has their own login (no shared logins) so everything is traceable. Auto logout after 15 min idle.
  • Store time in UTC, show in local time.
  • If two people save a reading for the same patient at the same time, the second one gets 'already recorded by X at time'.
  • Don't show patient names in phone lock screen notifications.
